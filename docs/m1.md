# M1 核心扫描实现记录

> 状态：COMPLETE（M2 开始前的遗留门禁已闭环）

## 已实现

- 多信号 Shopify 检测：MAIN runtime、generator、Shopify CDN/theme asset、canonical/myshopify、meta endpoint、checkout hand-off 与 cart-context 都以有界 Evidence 参与判定。
- `storefrontKind`：`hosted-theme` 必须同时满足 theme runtime、托管主题资产与匿名 `cart.js` Schema；custom/uncertain 不得进入 Ajax 产品链。
- B 级能力探测：`meta.json` 返回值经过 allowlist Schema 与字段裁剪；`products.json` 每次扫描先执行 `page=1&limit=1` capability probe。
- 产品分页：默认上限 1,000、每页 250、页码单调递增，并实现空页、短页、重复页签名、无进展、产品上限五类终止条件。
- hosted 降级链：`products.json → sitemap → Collection HTML → 限量 product .js`。Collection 只有在发现严格下一页链接时翻页，每个集合最多 20 页；`all` 无产品时最多尝试 10 个页面公开发现的集合。challenge、430、密码页属于 origin 级终止，不继续降级。
- 真实 Shopify 产品 sitemap 的 `from/to` 边界以最多 20 位十进制字符串解析并由 RequestPolicy 重建；不接受任意 URL、任意查询参数或跨 origin sitemap。
- custom/uncertain 通用路径：合并当前页面的同源 canonical、DOM 产品链接、经过裁剪的 JSON-LD `Product` 与同源 sitemap；不会调用 cart/product Ajax（分类所允许的一次 cart-context probe 除外），覆盖率始终按 partial/unknown 表达。
- Collector 页面适配器：最多检查 20 个 JSON-LD 块、256 KiB 文本预算、500 个遍历节点，只返回最多 100 个候选的 URL/标题/图片/来源；offers、价格与原始页面对象均不跨探针边界。无 id/handle 的 custom product 以清洗后的 canonical URL 作为本地稳定键。
- 持久化：产品按最多 100 条写入 staging；detection/catalog 模块、产品 manifest 与快照草稿齐备后原子 commit。取消/失败清理 staging，读路径只见 committed snapshot。
- Side Panel：新增「扫描当前店铺（M1）」与取消入口，输出 Evidence、上下文、覆盖率、capability、终止原因、运行诊断、错误和产品样本。
- 显式取消：每次扫描生成独立 `scanId`；用户取消、页面导航、标签/窗口切换或会话吊销时，Service Worker 中止匹配扫描已经发出的 fetch，不再等待 12 秒超时。取消后 staging 仍按既有协议清理。
- 重试执行器：M1 已接入 M0 冻结策略；429 使用 Retry-After 或 2/4/8 秒预算并把并发状态降为 1，network/timeout/5xx 仅重试一次，终止类别不重试。实际次数、累计等待、最终并发、降并发次数与有界事件现写入快照及 catalog module result。
- 匿名上下文：同一 SW/origin/routeRoot/omit 传输读取有界 `page-html`，只解析 ISO 校验后的 `Shopify.country`、locale 与 active currency；与页面会话及 `cart.js` 不一致时置 `contextMismatch`。
- B 级价格来源：按精确 product/variant ID 抽样核对官方 `.js` 端点；只有 hosted theme、匿名 country、cart currency、无上下文冲突且所有实际价格来源均 verified 时，`priceContextVerified=true`。
